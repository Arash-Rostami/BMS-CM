# BMS-CM JavaScript / Alpine.js Pattern

Verified against source on branch `master` (2026-07-25).

## Purpose

BMS-CM's browser interactivity is a small, hand-rolled Alpine.js layer: five pure-function factories (`landingPage`, `triWidget`, `search`, `workspace`, `workflow`) wired through a single `alpine/loader.js` hub, plus standalone panel-wide scripts (`filament/nav-dock.js`, `filament/topbar-autohide.js`, `filament/table-density.js`, `filament/fullscreen.js` toggles that use `Alpine.store` directly, and `filament/recents.js`, a store-less visit recorder for the topbar Recent-records dropdown). No build-time framework, no PWA/service worker, no Three.js, no global Proxy hub.

## Core idea

**Centralized registration + pure factories + lazy `Audio` + localStorage persistence.** Every Alpine component is `function Name()` returning a plain object — never `class`, never `new`, never `Alpine.store()` inside a landing-page factory. `alpine/loader.js` is the single place every factory is registered (`Alpine.data(name, factory)`, one hub, never scattered across files) — simplified 2026-09-25 from an earlier DOM-presence-gated version (`if (document.querySelector(...)) Alpine.data(...)`): `Alpine.data()` only stores a name→factory mapping, it never invokes or instantiates anything, so gating the registration call itself bought nothing — the factory only ever actually runs when Alpine's DOM walk finds a matching `x-data="Name(...)"` element, register-gated or not. Heavy objects (`Audio`) are created on first use, not in `init()`. Cross-session state survives in `localStorage`; in-session cross-component state survives via `window` `CustomEvent`s.

BMS-CM deliberately avoids a Proxy-hub/store-based architecture (centralized `Alpine.store()`, PWA caching, shared mixins): each landing-page component owns its local state and persists only what a user would notice losing (theme, active tab, pinned shortcuts). The four panel-wide toggle scripts are the one exception — they use `Alpine.store()` because they need to react across full Livewire SPA navigations, not just within one component tree (see §10).

## Directory & entry pipeline

```
resources/js/
├── app.js                                  ← Vite entry for the landing page (imports bootstrap + alpine/loader.js)
├── alpine/
│   ├── loader.js                           ← registration hub — stays at the alpine/ root, not nested
│   └── components/
│       ├── landing-page.js                 ← landingPage()
│       ├── tri-widget.js                   ← triWidget()
│       ├── search.js                       ← search()
│       ├── workspace.js                    ← workspace(config)
│       └── workflow.js                     ← workflow(groups)
└── filament/
    ├── theme.js                            ← separate Vite entry, panel-wide; window.setTheme() palette switcher
    ├── nav-dock.js                         ← separate Vite entry, Filament-panel-wide (NOT an alpine/ factory)
    ├── topbar-autohide.js                  ← same category as nav-dock.js
    ├── auto-close.js                       ← same category; Livewire-hook-based, no Alpine.store
    ├── table-density.js                    ← same category as nav-dock.js/topbar-autohide.js; window.setTableDensity()
    ├── table-stacking.js                   ← same category; window.setTableStacking() classic/stacked mobile-layout opt-out
    ├── fullscreen.js                       ← same category; browser-is-source-of-truth, no localStorage persistence
    ├── recents.js                          ← no store, no alpine:init; records visited record-edit pages into localStorage['recent_records']
    └── filepond-locale.js                  ← no store; one-shot FilePond.setOptions() patch for a missing fa locale label, retried until window.FilePond exists

vite.config.js
└── input: resources/js/app.js, resources/js/filament/{theme,nav-dock,topbar-autohide,auto-close,table-density,table-stacking,fullscreen,recents,filepond-locale}.js
    └── viteStaticCopy targets: resources/img, resources/audio, resources/video, resources/fonts
```

**Naming convention — kebab-case, always, project-wide across ALL of `resources/js/`, not just `filament/`, formalized 2026-09-25.** A single-word script stays single-word (`theme.js`, `app.js`, `loader.js`, `bootstrap.js`, `search.js`, `workflow.js`, `workspace.js`, `fullscreen.js`); anything with more than one concept in its name is hyphen-separated (`nav-dock.js`, `topbar-autohide.js`, `table-density.js`, `auto-close.js`, `landing-page.js`, `tri-widget.js`) — never a fused compound (`autoclose.js`, `navdock.js`, `landingpage.js`). This matches the same one-word/kebab-case rule this project already applies to `themes.css` palette keys (§1b) and to component filenames elsewhere in the codebase — one convention, not a JS-specific or `filament/`-specific exception. `auto-close.js` was renamed from `autoclose.js` to close the one drift instance found (asset id updated to `auto-close-js` alongside it, in `FilamentAssets.php`/`vite.config.js`/`CLAUDE.md`). **Verified 2026-09-25 against every `.js` file in the project (all 14, both `alpine/` and `filament/`) — every remaining file already conforms.** Any new script added to either directory must be named to this same standard from the start; there is no exception for a "temporary" or "quick" script name.

**Why `filament/*.js` isn't in `alpine/`:** organized by *where it runs* (inside the Filament panel itself, loaded via `FilamentAssets.php`'s `Js::make()`) not *what it is*. The `alpine/` folder is organized by the other axis — every file in it is a pure-function factory registered through `alpine/loader.js`, used only within the landing page's own Alpine scope. Mirrors the `resources/views/filament/` vs `resources/views/livewire/` split (see `resources/views/viewsPattern.md`).

**Registration flow:** Vite bundles `app.js` + the five factory modules into one asset → `app.js` imports `./alpine/loader.js` → the loader listens for `alpine:init` and registers all five factories unconditionally with `Alpine.data(name, factory)` → `Alpine.start()` runs once, guarded by `window.__alpine_running`.

## 1. The registration hub — `resources/js/alpine/loader.js`

```js
import Alpine from 'alpinejs';
import landingPage from './components/landing-page.js';
import triWidget from './components/tri-widget.js';
import search from './components/search.js';
import workspace from './components/workspace.js';
import workflow from './components/workflow.js';

window.Alpine ??= Alpine;

document.addEventListener('alpine:init', () => {
    Alpine.data('landingPage', landingPage);
    Alpine.data('triWidget', triWidget);
    Alpine.data('workflow', workflow);
    Alpine.data('search', search);
    Alpine.data('workspace', workspace);
});

if (!window.__alpine_running) {
    window.__alpine_running = true;
    Alpine.start();
}

export default Alpine;
```

- All five factories register unconditionally, regardless of whether a matching `x-data` element exists on the current page — simplified 2026-09-25 from an earlier version that gated `landingPage`/`triWidget`/`workflow` behind a `document.querySelector(...)` presence check. That gate bought nothing: `Alpine.data(name, factory)` only inserts a name→factory mapping into a registry, it never invokes the factory — the factory only ever actually runs later, when Alpine's own DOM walk finds a real `x-data="Name(...)"` element and instantiates it. A page with no `landingPage()` element on it registers the name for nothing, at negligible cost, exactly as before.
- `window.Alpine ??= Alpine` exposes the instance globally exactly once (`??=` no-ops if something already set it), since the `filament/*.js` panel-wide toggle scripts (a separate Vite entry, loaded on panel pages only) read `window.Alpine` directly.
- `window.__alpine_running` is checked before entering the block, and set to `true` BEFORE calling `Alpine.start()` (not after, contrary to an earlier draft of this doc) — prevents double-init if the bundle is evaluated twice.

## 2. Factory signature rule (all five factories)

```js
export default function Name(args) {
    return { /* plain object */ };
}
```

No `class`, no `new`, no `Alpine.store(...)`. Configuration enters via function arguments (`workspace` and `workflow` each take one); state leaves via `localStorage`, `window` events, and the DOM.

## 3. `landingPage()` — `alpine/components/landing-page.js`

```js
darkMode: false, activeTab: 'workflow', widgetOpen: false, widgetMinimized: false,
panelOpen: false, isWide: window.innerWidth >= 1024,
init() {
    // reads 'theme' (truthy set: '1'/'true'/'dark'/'on'), 'lp_tab', 'lp_widget_min', 'lp_widget_open'
    // toggles html.dark, listens for 'dark-mode-toggled', then $watch()es all four back to localStorage
    // plus a resize listener keeping isWide in sync with the viewport
}
```

- `darkMode` default `false`; `activeTab` default `'workflow'` (only overridden when `lp_tab` is non-null).
- `panelOpen`/`isWide` are the below-lg responsive state for the landing switchers (see `viewsPattern.md`): the corner FAB flips `panelOpen`, and the switcher column shows while `isWide || panelOpen`. `window.innerWidth >= 1024` — not `matchMedia('(min-width: 1024px)')` — because jsdom has no `matchMedia` (its default `innerWidth` is 1024 and is settable per test).
- `widgetOpen`/`widgetMinimized` together gate the floating `triWidget` panel: `widgetOpen && !widgetMinimized` shows the full panel, `widgetOpen && widgetMinimized` shows a small opposite-corner dock button. Both persist independently (`lp_widget_open`/`lp_widget_min`) — they used to disagree after a reload (widget appeared to "randomly vanish") before `widgetOpen` persistence was added. Minimizing never touches `triWidget`'s clock/timer/music state, only visibility (`x-show`, not teardown).
- Both `widget.blade.php` wrappers carry `x-cloak` — prevents a hydration-frame flash of the wrong panel before Alpine evaluates `x-show`.
- `localStorage` reads/writes are wrapped in module-level `getItem`/`setItem` helpers that swallow quota/privacy-mode failures. Replicate this for any new key.
- The Three.js torus background is gone — do not reintroduce.

## 4. `triWidget()` — `alpine/components/tri-widget.js`

Three tabs: Clock / Timer / Music. State: `tab: 'clock'`, `clockString`/`dateString`/`shamsiDateString`, `timer: {running, seconds: 300}`, `customMins`, `alarm: 'alarm.mp3'`, `alarmInterval`, `alarmAudioInstance`, `music: {tracks: [...4 local...], idx, audio, playing, position, duration, progress, volume: 0.8}`.

**Clock:** `_tick()` runs on its own `setInterval` (`_clockTimerId`), sets `clockString`/`dateString` via `toLocaleTimeString()`/`toLocaleDateString()`, and `shamsiDateString` via `toLocaleDateString('fa-IR', {..., numberingSystem: 'latn'})`. No `calendar: 'persian'` key — `fa-IR` resolves to the Persian calendar implicitly; `numberingSystem: 'latn'` forces Western digits.

**Timer:** `_countdownTick()` runs on a separate `setInterval` (`_countdownTimerId`); at 0 it stops and calls `startAlarmLoop()`. Presets are exactly 300/600/900/1800/3600 seconds (5/10/15/30/60 min) via `setTimerPreset(seconds)`.

**Alarm (lazy `Audio`):**
```js
startAlarmLoop() { this.stopAlarm(); /* new Audio, loop=true, play(), setInterval(stopAlarm, 60000) */ }
stopAlarm() { /* clearInterval + null the interval handle; pause + reset + null the Audio instance */ }
```
Created only in `startAlarmLoop()`, never in `init()`. Auto-stop is a **one-shot `setTimeout`** (changed from a self-clearing `setInterval` 2026-09-25 — the interval version only ever fired once by convention anyway, since `stopAlarm()` immediately clears it; `setTimeout` expresses that same one-shot intent natively, simpler) — `stopAlarm()` guards on `if (this.alarmInterval)` before clearing (`clearTimeout`, not `clearInterval`), so it's safe to call again even after it already fired. Keep this shape.

**Music (lazy `Audio`, reused across tracks):**
- `loadCurrentTrack()` creates the single `Audio` instance on first call (`preload='none'`, volume seeded from `music.volume`), wires `onloadedmetadata`/`ontimeupdate`/`onended`. The final `src` assignment is guarded (`!audio.src || !audio.src.includes(currentTrack.src)`) so re-selecting the same track doesn't restart it.
- `next()`/`prev()` call a shared `_switchTrack(idx)` which updates `idx`, persists, and swaps only `audio.src` — never recreates the `Audio` object.
- `playPause()`/`_switchTrack()` route through `_broadcastAndPlay()`, which dispatches `lp-audio-play` (`{source: 'widget'}`) **before** calling `.play()` — see §7.
- `init()` registers a `lp-audio-play` listener (`_onExternalPlay`) that pauses `music` if another player (`workflow`) starts; `destroy()` tears down both intervals and this listener.
- Four local tracks (`LoFi`/`Vocale`/`Pomodoro`/`Electronic`) served from `/audio/music/*` (Vite static-copies `resources/audio/*`). Cover art (`/img/widget/*.png`) is lazy-bound (`:src="music.playing ? currentTrack.image : ''"`) so it's only fetched during playback.
- `idx`/`volume` persist to `localStorage['lp_music']` (JSON), restored via `_loadMusicPrefs()` in `init()`. Browsers block autoplay after reload — only the *selection* is restored, not playback.
- The widget mounts once on the landing-page root (outside the tab panels), so closing/switching tabs never destroys the `Audio` — only `x-show` hides it. The panel won't `@click.away`-close while `music.playing`; the explicit X button (`stopMusic()`) is the only way to close-and-stop.

## 5. `workspace(config)` — `alpine/components/workspace.js`

Spread into the Blade's outer Alpine scope: `x-data="{ ...workspace({{ json_encode($workspaceConfig) }}), showModulePicker: false, showRecordPicker: false }"`.

**Storage:** `localStorage['user_shortcuts']` = `{ modules: [...ids], records: [...pins] }`, pin shape `{key, resourceId, recordId, label, subtitle, url}`. `readStorage()` migrates the legacy bare-array shape (`[...]` → `{modules: parsed.map(id), records: []}`) — keep this migration, old users still have it.

**Record search (in-flight request cancellation, `AbortController` — replaced the old `recordReqId` counter 2026-09-25):** `searchRecords()` aborts `this._abortCtrl` (if one is in flight) before issuing a new `fetch()`, then hands the new controller's `signal` to `fetch()` itself — a superseded request is genuinely cancelled at the socket level, not just ignored on resolution. The `catch` block returns early on `e.name === 'AbortError'` (an aborted request's own rejection, expected and silent); the `finally` block only flips `recordLoading` back off when `!this._abortCtrl.signal.aborted`, so an aborted call never clobbers the state a NEWER call already set. Any new call (including the clear-search button in `workspace.blade.php`) aborts the previous one this same way. Never bypass this with a fire-and-forget fetch — see §11 for why this replaced the old manual request-ID counter, and why it's now the mandatory shape for any new cancelable-request code in this codebase.

**`decorateRecord(p)`** merges a pin with its parent module's `icon`/`theme` (fallback `from-slate-500 to-slate-600`).

**`initials(value)`** — empty/whitespace-only input returns `'#'`; otherwise splits on `/[\s\-_/.]+/` and takes first letters of the first two words, or (single-word fallback) the first two alphanumeric characters uppercased — a value with exactly one alphanumeric character returns that one character, not `'#'`. Only zero alphanumeric characters falls through to `'#'`.

**Accordion-open invariant:** `modulesOpen`/`recordsOpen` each init to `true` only if their *own* section has ≥1 pin — never OR-in an `=== 0` fallback on the other section's count, or both stay permanently open.

**`recordsUrl` contract:** the Blade passes `url('/workspace/records/__RES__')`; the factory does `recordsUrl.replace('__RES__', pickerResource)`. No compile-time check links the two sides — change both together.

**`recentCandidates()` tamper hardening:** the picker's recents section reads `localStorage['recent_records']` (written by `filament/recents.js`), and every entry is re-validated before it becomes a clickable suggestion — a record is only offered when its `slug` matches the picker's module AND its `url` is a string starting with `/dashboard/` (same prefix guard as the work-actions recents popover; a tampered `javascript:`/off-site url never reaches the suggestion's `:href`).

## 6. `search()` — `alpine/components/search.js`

```js
searchQuery: '', isSearching: false, results: [], selectedResult: null, byUser: null,
chain: [], chainLoading: false, chainError: false,
breadcrumb: { purchaseRequest, proformaInvoice, purchaseOrder, registeredOrder, bankProfile, payment, shipment, custom }  // 8 keys, each {state, label}
```

- **`performSearch()`** — debounced 500ms in the Blade (`@input.debounce.500ms`, not in JS), `GET /api/search/spotlight?q=`. Reads `r.data.by_user` (snake_case — matches the API payload; not `byUser`). Does **not** touch `breadcrumb`. `performSearch()`/`selectResult()` capture `const ctrl = this._searchCtrl` / `this._chainCtrl` at request time and gate `catch`/`finally` on the call's OWN `ctrl.signal.aborted` — never on `this._xxxCtrl.signal`, which by rejection time already points at the NEWER call's controller (live race fixed 2026-10-09: a superseded request's late abort-rejection used to wipe the newer results and clear the loading flag early).
- **`selectResult(result)`** — sets `selectedResult`, then (if `result.type`/`result.id` present) lazily loads `GET /api/search/chain?type=&id=` into `chain[]`, and replaces `breadcrumb` wholesale from the response (`r.data.breadcrumb`). This is the only place `breadcrumb` changes — the spotlight response no longer drives it, so there's no pre-selection flash of wrong states.
- **`clearSelected()`** resets `selectedResult`/`chain`/`chainError`.
- **`getOffset(p)`/`getOffsetL(p)`** — SVG progress-ring stroke-offset for the small/large ring (`circumference - (p/100) * circumference`), circumferences precomputed from `r=16`/`r=22`.
- **`breadcrumbStages()`** — maps the `breadcrumb` object into an ordered array with `isLast` for template iteration.
- Focus trap (`tab-search-focus` → `$refs.searchInput?.focus()`) and both debounces are wired in the Blade, not this file.

## 7. `workflow(groups)` — `alpine/components/workflow.js`

Powers the Workflow tab: 4-stage stepper cards with Listen/Watch/Poster/Guide affordances plus an auto-rotating tips ticker. The only factory besides `workspace` that takes an argument, and the only one using a **prefix-match** registration guard.

```js
groups, tips: [], rotateIdx: 0, playing: false, audio: null,
selected: null, textOpen: false, videoOpen: false, paused: false, rotateInterval: null,
accentMap: { blue: {border,bg,text}, green, yellow, red },  // must stay 1:1 with workflow.blade.php's PHP $accent map
```

- `groups` arrives via `x-data="workflow(@js($insightGroups))"`, server-built by the `Workflow` Livewire component — hence the prefix-match guard (`workflow(...)`, never literal `workflow()`).
- `flattenTips()` builds the ticker's flat `tips[]` from each group's `tips[]`. `startRotate()` (7000ms) skips a tick while `textOpen`/`videoOpen`/`playing`/`paused` (hover); `togglePause()` toggles `paused`. `prefers-reduced-motion` disables auto-rotation entirely. Ticker is `x-show="tips.length >= 2"` + `x-cloak` — silent until ≥2 authored tips exist.
- `openText(group)`/`openVideo(group)` set `selected` then toggle `textOpen`/`videoOpen`; `openVideo()` calls `stopAudio()` first so narration and video never overlap. Both modals must stay inside the single `workflow(...)` root or their `x-show` bindings break.
- `playPause(group)` creates a fresh `new Audio(group.audio)` per play (narration is short, one-shot — reuse buys nothing), dispatches `lp-audio-play` (`{source: 'workflow'}`) before playing, and nulls the instance in `stopAudio()`.
- Each stage card's four buttons are gated server-side per `$insight` field: Listen (`@click="playPause"`), Watch (`@click="openVideo"`), Poster (plain `<a href target="_blank">`, no JS — `href` is `asset()`-generated, never user input), Guide (`@click="openText"`). `hasContent(group)` is the JS mirror of Guide's server-side `terms/process/dos/donts` gate.
- **Blade gotcha:** put Alpine `:class` on a raw `<span>`/`<svg>` wrapper, never directly on an `<x-heroicon-*>` Blade component — Blade PHP-evaluates the expression on component attributes and fatals ("Call to undefined function").

|---|---|---|---|---|
| `dark-mode-toggled` | `window` `CustomEvent` (boolean detail) | `filament/theme.js` `applySavedDarkMode()` (cross-tab dark-mode sync, 2026-10-10) | `landing-page.js` `init()` | `switchers.blade.php` still mutates `darkMode` directly in the same Alpine scope for its own clicks; the theme.js producer exists so the landing factory's state follows when ANOTHER tab changes the mode (the `storage` event handler and the visibilitychange backstop both route through `applySavedDarkMode()`). |

The six landing-page keys go through helper functions that wrap reads/writes in try/catch (quota/privacy-mode failures swallowed) — replicate that for any new landing-page key. The panel-wide toggle keys don't follow that shape: `topbar_pinned` is written directly from Blade `x-on:click` in `topbar-pin-toggle.blade.php` (no factory, no try/catch); `nav_dock`/`table_density` go through their own `window.setXxx(mode)` global instead (still no try/catch); `fullscreen` has no `localStorage` key at all (see the `fullscreen.js` bullet below — the browser's own `document.fullscreenElement` is the source of truth, not a persisted value). ## 10. Filament panel-wide scripts — `resources/js/filament/*.js`

**Every file in this directory MUST wrap its entire top-level body in an IIFE — `(function () { ... })();` — no exceptions, formalized 2026-09-25 after a real production break.** These load as classic `<script src="...">` tags (via `FilamentAssets.php`'s `Js::make()`), NOT ES modules — unlike `alpine/components/*.js` (which use `export`/`import` and get scope-isolated by Vite's bundler automatically), classic scripts loaded side-by-side on the same page share ONE global lexical scope. A bare top-level `const`/`let` in one file collides with a same-named one in another the moment both are minified down to a short identifier by esbuild — and esbuild picks short names independently per file, so two unrelated files can easily both land on `const a` or `const r`. **Live bug, 2026-09-25**: once this directory grew to 6 files (`theme`, `nav-dock`, `topbar-autohide`, `auto-close`, `table-density`, `fullscreen`), two pairs collided (`theme.js`/`table-density.js` both minified their first `const` to `a`; `topbar-autohide.js` and another file both landed on `r`) — the SECOND colliding script to execute threw `Uncaught SyntaxError: Identifier '...' has already been declared` and died completely before its `alpine:init` listener ever registered, silently killing that toggle (pin, theme, and table-density all went dead simultaneously, with zero server-side or build-time indication anything was wrong — `npm run build` succeeds fine, since each file is independently valid; the collision only exists once multiple compiled files share one page). The IIFE gives each file its own function scope, so no future file — regardless of how many are added, or what esbuild names its locals — can ever collide with another again. **When adding a 7th (or Nth) file here, wrap it from the start; do not wait to find out the hard way.**

Shipped shape, differs from the second attempt in three ways:
1. **Session, not a cookie** (`session('row_click_edit', false)`, boolean) — a cookie written by plain client JS isn't in Laravel's encrypted format, so `EncryptCookies` silently nulls it on read; this project's existing toggles (`TableStateToggle`/`CalendarToggle`) are already session-backed for the same reason, and `RowClickToggle` now mirrors them exactly — a real Livewire component, no JS file, no `localStorage` (see `app/Livewire/livewirePattern.md`).

3. **Test the rendered markup, not just the getter** — a `getRecordUrl()`/`getRecordAction()` assertion is exactly the blind spot that let the second attempt ship green while broken live. **Tooltip lesson (applies project-wide):** a tooltip whose content is a plain PHP string baked into static HTML by a Livewire server round-trip (e.g. `calendar-toggle.blade.php`'s `$tooltip`) is reliable by construction. `nav-dock`/`topbar-pin` have no server round-trip (pure client-side `Alpine.store` + `localStorage`) — reaching for a client-JS-computed `x-tooltip` content expression on a single button is the wrong shape and is unreliable. **`theme.js`** (added 2026-09-22) is the smallest of the four — no `alpine:init`, no `Alpine.store`, no double-bind guard: it just defines `window.setTheme(key)`, which validates the key against `window.BMS_THEMES` (exported by `filament/partials/meta.blade.php` from `config('palettes')` — the canonical list lives in PHP, JS holds none), falls back to `'slate'`, persists to `localStorage['theme_palette']` (try/catch, quota/privacy-safe), sets `document.documentElement.dataset.theme`, and dispatches `palette-changed` (deliberately NOT `theme-changed` — that name is Filament's own dark/light persistence hook; see the events table). A `livewire:navigated` re-apply handler IS required (live bug 2026-09-22): `->spa()` morphs never replace `<html>` itself, but they DO sync its attributes against the incoming server HTML — which has no `data-theme` (client-only attribute), so every module change morphed the attribute away and reset the palette to slate until reload. `html.dark` survives only because Filament's own Alpine effect re-applies it on every tick; the palette has no such owner, hence the explicit listener. The pre-paint apply happens in the meta partial's inline script, not here (Vite JS is deferred; only inline head JS runs before first paint). The load-time `applySavedTheme()` call at the end of the IIFE is the event-independent backstop (live bug 2026-10-10: the palette reset on SPA arrival at the landing page even with both listeners registered — `livewire:navigated` is deferred behind `mergeNewHead()`'s remote-script promises and `onSwap` never ran there): `@filamentScripts` renders this file as a plain `<script>` in the `<body>` of BOTH the panel base layout and the landing layout, and Livewire's `prepNewBodyScriptTagsToRun()` re-clones every body script without `data-navigate-once` on each `wire:navigate` swap, so the whole IIFE — and therefore the re-apply — re-executes in the same frame the new body connects, on every page, regardless of event delivery. On top of those same-tab mechanisms, two cross-tab listeners complete the sync (live bug 2026-10-10, two tabs open side by side): a `window` `storage` listener (fires ONLY in other tabs when `setTheme` writes `localStorage['theme_palette']` — the writing tab never hears it) and a `document` `visibilitychange` re-apply as a focus-time backstop — together the palette flows live in BOTH directions between any open tabs (panel ↔ landing), matching the sibling Fateh project's `ThemeManager` pattern. Dark/light mode rides the same two listeners through `applySavedDarkMode()`: on a `storage`/`visibilitychange` hit for the `'theme'` key, it re-dispatches Filament's own `theme-changed` event with the raw `'dark'`/`'light'` payload (vendor `dark-mode.js` updates its Alpine store, persists, and toggles `html.dark` — never re-implement that) plus a boolean `dark-mode-toggled` so the landing factory's `darkMode` state follows; `landing-page.js` and Filament's dark toggle are UNTOUCHED — the sync is layered on their existing events.

**Blade evaluation gotcha (found live 2026-09-22):** never put Alpine shorthand `:attr="expr"` on an `<x-*>` component tag (e.g. `:aria-expanded="open"` on `<x-icon-button>`) — Blade PHP-evaluates `:`-prefixed attributes on component tags and fatals with `Undefined constant "open"`. Use the long `x-bind:attr="expr"` form on components (passes through untouched for Alpine); shorthand `:attr` is only safe on raw HTML elements.

## 11. Verified performance standards (formalized 2026-09-25, mandatory for all new code in this layer)

A full-codebase refactor pass claimed six categories of "enterprise-grade" optimization. Each was independently verified against actual Alpine/`@vue/reactivity` source and the real compiled output before being accepted here — one claim (below) was disproven and corrected; the rest hold up and are now standard.

**Closure-scope hoisting for large static/read-only data (the real Proxy-evasion mechanism).** Alpine wraps every property inside a component's `return {}` object in a reactive Proxy — including large, never-mutated arrays like `WIDGET_TRACKS` (`tri-widget.js`) or the module list a `workspace(config)` factory receives, which costs real, avoidable Proxy-wrapping overhead for data that never needs change-tracking in the first place. **The underscore prefix on internal fields (`_audioInst`, `_abortCtrl`, `_searchCtrl`, `_rotateTimer`, `_cachedStages`) does NOT do this** — verified directly against `node_modules/alpinejs/src/reactivity.js` and the underlying `@vue/reactivity` Proxy `baseHandlers`: neither has any underscore-prefix special-casing, and a property returned inside the component object gets wrapped identically regardless of its name. Keep the underscore purely as a **lexical convention** — "this is internal bookkeeping, never bind it in a template expression" — it's a readability signal for humans, not an instruction to the framework. The actual technique that isolates data from the reactivity engine: declare it as a `const` in the **factory function's closure**, outside the `return {}` block entirely (`rawModules`/`rawStats`/`rawRecordsUrl`/`moduleMap` in `workspace.js`; `WIDGET_TRACKS` in `tri-widget.js`; `ACCENT_MAP` in `workflow.js`; `DEFAULT_BREADCRUMB`/`DEFAULT_STAGES` in `search.js`) — a closure variable is never a property of the reactive object, so it's never Proxy-wrapped, full stop, regardless of naming. Expose it to templates via a getter (`get modules() { return rawModules; }`) if needed; the getter's RETURN VALUE still gets wrapped on template-side access, but the closure's own internal reads/loops bypass the Proxy entirely.

**`Set`/`Map` for lookups — use at real scale, not for small fixed lists.** Genuinely worth it once a lookup set is large enough or hot enough that linear scan cost is measurable (`workspace.js`'s `moduleMap`, ~15 modules, read on every pin/unpin). NOT worth it for a fixed 3-11 item validation list (`NAV_MODES`, `TRUE_SET`, a palette-key check) — V8 already handles `.includes()`/`.find()` on arrays this small in effectively the same time, and the `Set`/`Map` framing ("O(N) → O(1)") is Big-O-correct but practically meaningless at this N. **Never reconstruct a `Set` inside a function that runs on every render/call** just to do a small negate-filter — allocate it once outside the hot path (or just use `.includes()` on the small array directly) rather than paying a fresh allocation cost every call to save a scan that was already cheap.

**GC-friendly allocation patterns — hoist what's genuinely reused, don't chase micro-wins that cost readability.** Worth doing: hoist string/regex constants used repeatedly to module scope (`REGEX_SPLIT`/`REGEX_ALNUM` in `workspace.js`, every event-name/storage-key constant) instead of re-creating them per call; precompile `Intl.DateTimeFormat` instances that get reused indefinitely (`DATE_FMT`/`SHAMSI_FMT` in `tri-widget.js`, reused every second for as long as the clock is open — `Intl.DateTimeFormat` construction has a real, documented locale-resolution cost, so this one is a genuine win); prefer a single-pass `for`/`for...of` loop over a `.filter().map().flatMap()` chain when building one output array, since the chain allocates and discards an intermediate array per link. NOT worth it: replacing `Math.floor(n / 60)` with `(n / 60) | 0` in a value that updates once per second — the bitwise form is not measurably faster at this call frequency and trades away readability for no real gain; this project doesn't mandate one over the other, use judgment, but don't frame a readability trade as a performance requirement.

**Render-throttling via a state gate before a reactive write.** `tri-widget.js`'s `_tick()` reads the clock every 1000ms (interval tick) but only writes `clockString`/`dateString`/`shamsiDateString` (all reactive, all trigger a re-render) when the actual displayed second has changed (`if (this._lastSec === s) return`) — this is genuinely worth doing for ANY high-frequency native event (`ontimeupdate`, `scroll`, `mousemove`) that fires far more often than the UI value it drives actually changes: gate the reactive write on "did the value a human would notice actually change," not on "did the event fire."

**`AbortController` for any cancelable network request — mandatory going forward, replaces the old manual request-ID counter pattern.** `search.js` (`_searchCtrl`/`_chainCtrl`) and `workspace.js` (`_abortCtrl`) both: abort the previous in-flight request before starting a new one, pass the new controller's `signal` into the request call, treat the abort rejection in `catch` as an expected no-op (not a real failure), and gate the `finally` block's state reset on the call's own captured signal — `const ctrl = this._xxxCtrl` captured at request time, checked as `!ctrl.signal.aborted` — so a cancelled call can never clobber state a newer call already set. **Never gate on `this._xxxCtrl.signal` directly**: by the time a superseded call's rejection lands, `this._xxxCtrl` already points at the NEWER call's controller, so the guard reads "not aborted" and the stale rejection wipes the newer state (live race, found by test 2026-10-09 and fixed identically in all three controllers). This is a genuine upgrade over a `reqId` counter (which only ignored a stale response after it resolved, wasting the network round-trip) — `AbortController` actually cancels the request. Any new fetch/axios call in this codebase that can be superseded by a later one (search-as-you-type, a picker's dependent lookup, anything re-triggered on user input) must use this shape.

## 12. JS test suite — vitest (added 2026-10-09, mirrors the sibling Fateh project's strategy)

Every JS file in this layer ships with co-located tests in a `__tests__/` folder beside its source (`resources/js/alpine/components/__tests__/`, `resources/js/filament/__tests__/`), one `*.test.js` per source file. Run with `npm run test` (`test:watch` for watch mode). Root `vitest.config.js`: jsdom environment, include `resources/js/**/__tests__/**/*.test.js`; `vitest` + `jsdom` are devDependencies only — no test file is imported by any Vite entry, so nothing leaks into the production bundle. Any new file in `alpine/components/` or `filament/` gets its own `__tests__/<name>.test.js` in the same turn.

- **Factory tests import the real factory** (`import search from '../search.js'`) and drive it directly: `c.$watch = vi.fn()` stub, mocked `axios`/`globalThis.fetch`, a `FakeAudio` class standing in for lazy `Audio` (its `play()` returns `Promise.resolve()`), `vi.useFakeTimers()` for intervals/timeouts, `localStorage.clear()` in `beforeEach`. State flipped inside `play().then(...)` is microtask-async — `await Promise.resolve()` before asserting it.
- **IIFE panel scripts load fresh per test**: `vi.resetModules()` + `delete window.__xxxBound` + `await import('../x.js')` + `document.dispatchEvent(new Event('alpine:init'))`. The `fakeAlpine()` harness must be REACTIVE — `store(name, value)` re-runs every registered effect on each write, `effect(cb)` registers then invokes once. A plain `effect(cb) { cb() }` fake silently misses store-write-driven re-applies (the html-class toggles look untested-broken).
- **Listener accumulation is the IIFE test leak**: re-importing re-binds that module's `alpine:init` handler, and since `load()` deletes the bound flag, every earlier handler re-registers its `livewire:navigated`/click listeners on each dispatch — earlier tests' handlers then mutate shared state (html classes, `localStorage`, the latest `window.setXxx`) on later tests' dispatches. Files whose tests dispatch those events (nav-dock, topbar-autohide) record every `document.addEventListener` call in `beforeEach` and remove all of them in `afterEach`. `recents.js` (listener-at-import, no bound flag) is instead imported ONCE per test file — re-importing per test multiplies its capture listeners.
- **Supersede tests must defer the stale rejection one macrotask** (`signal.addEventListener('abort', () => setTimeout(() => reject(...), 0))`): an immediate rejection settles before the newer mock response's continuation, so the stale wipe is overwritten before any assertion and the test passes even against pre-fix code. The deferred form makes the rejection land after the newer response — the exact real-world order that breaks the unguarded shape.
- Test files carry zero comments, same noise rule as source.

## Developer Decision Matrix

| When you need to… | Do this… | Why… |
|---|---|---|
| Add a new Alpine component | Create `alpine/components/<name>.js` exporting `function Name()`; import + register in `alpine/loader.js`. Gate with exact-match `[x-data="Name()"]` if argless, or prefix-match `[x-data^="name("]` if it takes a payload. | Keeps the hub the single registration point; `workflow(groups)` is the prefix-match precedent. |
| Coordinate two independent audio players | Dispatch `lp-audio-play` before `.play()`; listen for it in `init()`. | Matches the `workflow` ↔ `triWidget` bus — no singleton, no shared store. |
| Persist user-visible state across reloads | Add a `localStorage` key; wrap reads/writes in try/catch; read in `init()`, write in a `$watch`. | Matches the six landing-page keys in §9. |
| Debounce user input | `@input.debounce.Nms="handler()"` in the Blade, not `setTimeout` in JS. | Two debounce layers interact unpredictably. |
| Initialize a heavy object (`Audio`, `Worker`) | Create it on first use inside the handler that needs it, never in `init()`. | Avoids memory cost + autoplay-block warnings before any user gesture. |
| Guard an async fetch against stale responses | Abort the predecessor, pass the new controller's `signal`, and gate `catch`/`finally` on the call's OWN captured `ctrl.signal.aborted` — never `this._xxxCtrl.signal`. | See §11; `this._xxxCtrl` already points at the newer call when the stale rejection lands. |
| Add a tab to `triWidget` | Add the key to `tab`; gate any lazy `Audio` via `$watch('tab', ...)`; ship an inline heroicon SVG (no emoji). | Matches Clock/Timer/Music. |
| Change the workspace search URL shape | Update both `workspace.js`'s `recordsUrl.replace('__RES__', ...)` and `workspace.blade.php`'s `url('/workspace/records/__RES__')`. | No compile-time check links the two sides. |

## Absolute Anti-Patterns (Do Not Do This)

- ❌ **Reintroduce a Three.js/particle/torus background.** Deleted in the enterprise redesign; the landing page uses a CSS-only dot-grid now.
- ❌ **Use `class`/`new` for an Alpine component.** Breaks `Alpine.data(name, factory)`'s `this` binding and the `{ ...workspace(config) }` spread pattern.
- ❌ **Call `document.querySelector` inside an Alpine data function.** Use `$refs`/`$el`/`$watch`/event targets. Only `alpine/loader.js` may use it, as the registration guard.
- ❌ **Instantiate `Audio` in `init()`.** Alarm/music/workflow-narration audio are all lazy by design — early instantiation costs memory and triggers autoplay-block warnings.
- ❌ **Add `calendar: 'persian'` to an `fa-IR` date formatter.** `fa-IR` resolves to the Persian calendar implicitly; only `numberingSystem: 'latn'` belongs.
- ❌ **Recreate the music `Audio` instance on `next()`/`prev()`.** Only `audio.src` swaps via `_switchTrack()`; `loadCurrentTrack()` is the single creation site.
- ❌ **Put debounce logic in JS.** Debounces live in the Blade (`@input.debounce.Nms`) for both `search` (500ms) and `workspace` (300ms).
- ❌ **Assume `dark-mode-toggled` fires.** It has a listener but no producer — code depending on it silently never runs.
- ❌ **Swap the alarm auto-stop back to a self-clearing `setInterval`.** The one-shot `setTimeout` + guarded `clearTimeout` shape is intentional (see §4); keep it consistent.
- ❌ **Dispatch `tab-search-focus` without `$nextTick`.** Without it the search panel isn't mounted yet and `$refs.searchInput` is `undefined` (the listener's `?.focus()` is only a defensive no-op backstop).
- ❌ **Register `Alpine.data` outside `alpine/loader.js`.** Scattered registrations break the lazy/DOM-gated invariant.
- ❌ **Introduce `Alpine.store()` inside a landing-page factory, a Proxy hub, a service worker, or a PWA manifest.** The four `filament/*.js` panel-wide toggle scripts (`nav-dock.js`/`topbar-autohide.js`/`table-density.js`/`fullscreen.js`) are the only sanctioned `Alpine.store()` users, and only because they must survive Livewire SPA navigation — not a precedent for landing-page factories.
- ❌ **Bypass `_abortCtrl`/`AbortController` with a fire-and-forget fetch.** Every cancelable request in this codebase (`search.js`'s `_searchCtrl`/`_chainCtrl`, `workspace.js`'s `_abortCtrl`) aborts its predecessor before issuing a new request, and every `.catch`/`.finally` checks the signal before mutating state — see §11.
- ❌ **Change the `__RES__` placeholder contract on only one side.** `workspace.blade.php` and `workspace.js` must change together — no compile-time check.
- ❌ **Reach for a client-JS-computed tooltip `x-tooltip` content expression on a store-only toggle (no server round-trip).** See §10's tooltip lesson — use two static button variants instead.
