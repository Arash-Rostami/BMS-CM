Three classes, all serving Purchase Request's bulk import/export (`app/Filament/filamentPattern.md` §1.8a/§1.8b documents the full system these belong to — read that first):

- `App\Jobs\ImportCsv extends Filament\Actions\Imports\Jobs\ImportCsv` — the plain, non-grouped import job, wired via `App\Filament\Actions\ImportAction`. Purchase Request/Proforma Invoice/Registered Order all have item rows and use the grouped variant below instead; Bank Profile has no item rows at all, so `BankProfileImporter` was the first consumer of this plain job; Department (2026-09-26) is the second — same flat shape.
- `App\Jobs\ImportGroupedCsv extends Filament\Actions\Imports\Jobs\ImportCsv` — iterates parent+item GROUPS instead of individual rows, full group-atomic rollback on any item failure. Used by Purchase Request/Proforma Invoice/Registered Order, dispatched by `App\Filament\Actions\GroupedImportAction`.
- `App\Jobs\Export{PurchaseRequests,ProformaInvoices,RegisteredOrders,PurchaseOrders,BankProfiles,Departments,Correspondences,Payments,Shipments,Customs,Products,Banks}` — one per module with a bulk export action; each writes a CSV to `storage/app/exports/{user}/{file}.csv` via its own `{Module}Exporter::write()`, then notifies the user with a signed download link (success) or a generic error notification (failure, real exception goes to `report()`). `Product` (2026-10-06) is the third flat (non-grouped) `ImportAction`/`ImportCsv` consumer, mirroring Bank Profile/Department's wiring.

Test coverage mirrors every job class 1:1 in `tests/Feature/Jobs/` — 14 files: `ImportCsvTest`, `ImportGroupedCsvTest`, and `Export{PurchaseRequests,ProformaInvoices,RegisteredOrders,PurchaseOrders,BankProfiles,Departments,Correspondences,Payments,Shipments,Customs,Products,Banks}Test`. This is a genuine 4th test layer (Resource/Model/Service/Job), not folded into the owning resource's test file, since a Job has its own lifecycle (`middleware()`, `handle()`'s success/failure paths) independent of the Filament Action that dispatches it. See `tests/testPattern.md` §1. Known gap (as of 2026-10-06): no job test exercises `handle()`'s catch branch (`report()` + danger notification) — most export test files cover the success path only.

**Gotcha:** a long-running `queue:work` process caches class code in memory at boot — editing any of these classes (or anything they call) mid-session and testing from the actual running app, without restarting the worker (`php artisan queue:restart`), reproduces a stale-code bug that a fresh `php artisan tinker` invocation of the same job will NOT reproduce.
