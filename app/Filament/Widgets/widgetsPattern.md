# Dashboard Analytics Widgets

## Overview

The Filament `Dashboard` page (`App\Filament\Pages\Dashboard`, not the vendor default) is tabbed: `AccountWidget` always visible at the top, then 3 tabs — **Risk Overview**, **Performance**, **Exposure** — each holding 2 of the 6 analytics widgets. Adding a widget later is a one-line addition to `Dashboard::TABS`; adding a category is a new `Tab::make()` entry.

All 6 widgets are thin wrappers: each calls exactly one `App\Services\AnalyticsService` method and has no query logic of its own. Every `AnalyticsService` method does its aggregation (`SUM`/`CASE WHEN`/`DATEDIFF`/HHI math) in SQL, not PHP loops, and is cached individually via plain `Cache::remember('analytics:{key}', 300, ...)` — not `SmartCacheManager`, since these are cross-model aggregates, not one model's data (see `filamentPattern.md` §1.13 for the full caching contract).

## In-app legend (`HasMetricLegend` / `<x-metric-legend>`)

Every widget shows a collapsed-by-default "About this metric" disclosure under its chart/list, with four parts in order: **what it shows** (plain language), **data used** (models/columns, business-readable), **why it matters** (business value), and — separated by a fading horizontal divider — **technical** (the actual query logic: exact `table.column` names, join keys, `CASE WHEN`/`DATEDIFF` bucket boundaries), so both a non-technical user and a future maintainer can stop at the depth they need.

- `resources/views/components/metric-legend.blade.php` — the shared disclosure component (plain Alpine `x-data="{ open: false }"`, no dedicated JS file). Lives under `resources/views/components/` (the reusable-anonymous-component namespace, per `viewsPattern.md`), **not** `resources/views/filament/`, specifically so the `<x-metric-legend>` tag syntax resolves via Laravel's default anonymous-component convention. It also renders as a plain `view('components.metric-legend', [...])` (`ConcentrationRiskWidget`), where no `$slot` exists, so the optional slot (the calendar's rule-details card) is output as `{{ $slot ?? '' }}` — never a bare `{{ $slot }}` (that threw "Undefined variable $slot", fixed 2026-10-13; covered by `CalendarGridWidgetTest`).
- `app/Filament/Widgets/Concerns/HasMetricLegend.php` — trait providing `getLegend(): array`, reading `resources/dashboard/strings.php`'s `widgets.legend.{LEGEND_KEY}.{what,data,why}` keys via a `protected const LEGEND_KEY` on the widget class.
- **`ChartWidget` subclasses** (4 of them) use the trait + override `protected string $view = 'filament.widgets.chart-with-legend';` — a near-copy of Filament's own `chart-widget.blade.php` with one addition: a `<x-slot name="footer">` passed to `<x-filament::section>` (which already supports a `footer` prop/slot natively).
- **`ConcentrationRiskWidget`** (`StatsOverviewWidget`) has no such view hook — instead it overrides `getSectionContentComponent()` and calls the schema `Section::footer()` method (`Filament\Schemas\Components\Section` supports `->footer(string|Htmlable|...)` natively).
- **`PipelineStallWidget`** already owns its Blade view entirely, so the legend is just a `<x-slot name="footer">` added directly to its existing `<x-filament::section>`.

Testing gotcha: rendering a widget's own view or `getSectionContentComponent()` standalone via `view(...)->render()` in tinker throws `Using $this when not in object context` / `Typed property ...Component::$container must not be accessed before initialization` — artifacts of forcing Livewire/Schema lifecycle methods outside a real request, not real bugs. Verify these paths via `Blade::compileString()` + `php -l` on the compiled output instead — Page/Schema construction (e.g. `Dashboard::content()`) doesn't need a live Livewire request the way widget rendering does, so that path *does* work standalone in tinker.

## Report widgets live with their page

The charts and attention table of the report pages are NOT in this folder: they sit in `app/Filament/Pages/Reports/{Name}/` (shared base: `Pages/Reports/Widgets/ReportAttentionWidget`), and each is appended to `DashboardPanelProvider::widgets()` (required for their Livewire round-trips). Contract and layout: `app/Services/Reports/reportsPattern.md`.

## The 6 widgets

| Widget | Class | Legend key | Data used |
|---|---|---|---|
| Trade Cycle Time | `TradeCycleTimeWidget` | `cycle_time` | `purchase_requests.approval_date` → `registered_orders.order_date` (via `registered_order_purchase_request`) → the EARLIEST real `payments.payment_date` of that order (direct, or through a PurchaseOrder linked to exactly one order) → `shipments.exit_date` (actual departure) → `customs.clearance_date`. Chart labels carry the sample size (`n=`) |
| Concentration Risk | `ConcentrationRiskWidget` | `concentration` | `payments.payable_amount * exchange_rate` (Rial equivalent, non-void only) grouped by `payee_id` (supplier HHI) and by `currency_id` (currency HHI) |
| Shipment Punctuality | `ShipmentPunctualityWidget` | `punctuality` | `shipments.warehouse_date` (actual receipt) vs `shipments.eta` (estimated **arrival**); `exit_date` is departure from origin and is NOT comparable to an arrival estimate |
| Overdue Payment Aging | `ExposureAgingWidget` | `exposure_aging` | open payments (no `payment_date`, status not Draft/Rejected/Cancelled/Refunded/Completed) past `payment_deadline`, `payable_amount` per `currency_id`, bucketed 0-30/31-60/61-90/90+ |
| Open Currency Exposure | `OpenCurrencyExposureWidget` | `open_exposure` | `registered_order_items.line_total` (summed per order) minus SETTLED non-void `payments.payable_amount` in the order's own currency (direct, or through a single-order PurchaseOrder), clamped at 0 per order, grouped by `registered_orders.currency_id` |
| Stalled Files | `PipelineStallWidget` | `pipeline_stalls` | unapproved non-Authorized/Declined `purchase_requests.required_by_date`, `registered_orders.expected_delivery_date` (+ no linked Shipment), open `payments.payment_deadline`, `shipments.eta` with no `warehouse_date` and not Delivered/Arrived — each compared to `CURDATE()` |

Business-facing prose for all 6 lives in `resources/dashboard/strings.php`'s `widgets.legend.*` keys, all 3 locales. Don't let that copy drift from what the SQL actually does. Rules every metric must keep (each pinned by a fixture-based case in `AnalyticsServiceTest`, which asserts real numbers, not result shapes): never add amounts across currencies without converting them; ignore void (Draft/Rejected/Cancelled/Refunded) payments and cancelled/rejected shipments; count payments made on a linked PurchaseOrder; never net unpaid/planned or other-currency payments against order value; never compare a departure date to an arrival estimate. All six share the status helpers in `AnalyticsService` (see `servicesPattern.md`), and a stalled shipment is by construction a punctuality «currently overdue» shipment.

## Known scope limitations (intentional, not bugs)

- **Concentration Risk** assumes `payments.exchange_rate` converts that payment's currency to Rial (the form tooltip says "USD→Rial"); a non-USD payment entered with a USD→Rial rate would be mis-weighted. Confirm the data-entry rule before relying on the currency HHI.
- **Open Currency Exposure** nets only payments in the order's OWN currency and only POs linked to exactly ONE order; a payment in another currency, or on a PO shared by several orders, does not offset (it cannot be converted/allocated without guessing).
- **Shipment Punctuality / Stalled shipments** need `eta`; shipments without an ETA (most of the dev data) cannot be judged and are not counted.
- **Overdue Payment Aging / Stalled payments** need `payment_deadline`; open payments without one cannot age and are not shown.
- **Stalled Files** excludes Customs clearance — `customs` has no explicit target-date column to compare against (unlike the other 4 stages, which all have one), so it was left out of the UNION rather than force a weaker heuristic.
- MySQL 5.7 (this project's actual DB) has no window functions, so the percentile pick is deliberately PHP-side for every engine — durations are SQL-sorted (`ORDER BY stage, duration`) and PHP only does an O(1) index pick.

## Calendar tab (added 2026-10-08)

The Dashboard's FIRST tab is the Calendar Rules view: `CalendarGridWidget` (month grid + rule legend + guide, plain `Widget`) and `CalendarDayWidget` (the project's first `TableWidget`: card rows via `Stack` + `contentGrid`, paginated 5/10/25, grouped by module). `Dashboard::TABS` entries accept an optional per-tab `columns` / `spans` map (default 2 columns, so the other tabs are unchanged); the calendar tab uses a 10-column grid with spans 7 and 3. Both widgets are non-lazy and exchange state through the `calendar-day-selected` / `calendar-toggled` Livewire events; the query logic lives in `App\Services\Calendar\Display\CalendarBoard`, not in the widgets. Chrome strings are under `resources/dashboard/strings.widgets.calendar.*`, the legend footer under `legend.calendar.*`. The `<x-metric-legend>` component takes an optional `open` prop, a `generic` flag (false hides the what/data/why text) and a default slot; the calendar grid uses both to show the selected rule's details inside the guide (see `calendarPattern.md` §13). Both widgets keep every public property `mixed` and sanitised (a forged Livewire update never throws), and never read a `#[Computed]` in an action before changing the state it depends on (request-long cache). Full rules: `app/Services/Calendar/calendarPattern.md` section 9. Layout is responsive: the tab grid is `[default 1, lg 10]` and the widgets span `[default full, lg 7]` (grid) and `[default full, lg 3]` (day panel) — stacked full width on mobile, 70/30 from the `lg` breakpoint (asserted in `CalendarGridWidgetTest`).

### Day table filters and hide state (2026-10-11, reworded 2026-10-12)

`CalendarDayWidget` filters are classic native `SelectFilter`s («Scope»: One day default / Whole month; «Hidden items»: Not hidden default / Hidden / All) in the standard toolbar popover with the Apply button; the table query closure reads the validated values from `$this->tableFilters`. Defaults survive Reset (`resetState`), indicators show non-default choices only, and `syncSelection()` keeps the user's choices (no `resetTable()`). The grouping direction select is hidden (`groupingDirectionSettingHidden()`). Cards read the hide stamp from the `read_at` virtual column (`CalendarBoard::dayQuery/monthQuery` add `withReadAt`), so there is no per-card lookup; Hide / Show again never dispatches a bell event. `CalendarGridWidget` hides hidden items (`CalendarBoard::monthGroups` is always unread-only) and re-renders on `calendar-read-changed`. Full contract: `calendarPattern.md` §14.
